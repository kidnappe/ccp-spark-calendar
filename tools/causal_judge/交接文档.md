## 一、这个方向是怎么来的

1. 起点讨论：本地小模型除了星火日历的三个工具（OCR清洗/合并/详情丰富）还能干什么。
   结论是两层定位：
   - **确定性计算层**：力导向布局这类纯算法包成工具，让 Agent 别自己心算（省 token 是顺带，保证正确才是主要目的）；
   - **本地推理层**：摘要/分类/抽取类轻活交给 qwen，替云端大模型消化长文本。
2. 随后聚焦到具体痛点：**算法算出的因果边（交叉引用+TF-IDF）本质是相关不是因果，
   存量 451 条边里有混入的假边、也有缺书证的边**。
3. 决定先不写生产代码，先做**资格认证**：用项目里人工裁决过的历史决策当考卷，
   盲测本地模型能不能胜任"因果审核员"。即任务②。已考完，见下。

## 二、考试设计与三轮成绩

**考卷重建**（原 `.ocr/tier_plan1~5.json` 已随目录删除，git 也无记录）：
- 正例 causal 40 条 = 推断源边中现存 tier=verified 的（人工查书证后升级保留）
- 中例 background 42 条 = 同源但现存 background 的（人工认定仅背景/平行）
- 负例 unrelated 9 条 = backups 里上一版有、现在没有的边
  ⚠️ 这 9 条端点事件已从 events.json 删除，实际全部跳过——**unrelated 识别力至今未测**

**盲测方式**：只喂两端事件的文本块（v2 起含 ocrDesc），绝不含任何 tier 信息；
temperature=0；`format:json` 强制结构化输出；引文必须过程序化验伪
（去标点空白后须为材料原文子串，否则记伪引文）。

| 指标 | v1 裸考 | v2 +ocrDesc 书证 | v3 +三条规则 |
|---|---|---|---|
| 真因果识别（40 题） | 30 = 75% | 30 = 75% | 27 = 68% ↓ |
| 背景识别（42 题） | 21 = 50% | 28 = 67% | **35 = 83%** |
| 弃权 insufficient | 9 题 | 4 题 | 0 题 |
| 引文有效率 | 95% (41/43) | 85% (35/41) | 88% (30/34) |
| 总正确率 | 62% | 71% | **76%** |

**变量说明**：
- v1→v2 唯一变化：`block()` 补喂 ocrDesc 字段（《简史》OCR 碎片，419 条全有，共 5 万字）
- v2→v3 唯一变化：SYS 加三条硬规则（纪念不算因果 / 同类会议理论继承→background /
  组织人员直接延续是最强因果）

**三轮结论**：
1. 能白捡的分已经捡完，76% 逼近考卷信噪比上限（错题约三分之一本身标注可疑，
   如「宪法修正案→宪法修正案」重名事件、「十五大→十六大算因果」的宽松标注）。
2. 规则有副作用：治住假阳性（纪念类误判从 13 降到 ~5），但 rule6 一刀切误杀了部分真因果
   （召回 75%→68%）。这是 7B 执行规则的粒度极限，继续调 prompt 属于噪声里刨分。
3. 模型价值定位：**预筛不终审**。76% 自动一致 + 分歧全部转人工 = 复核工作量砍 3/4。

## 六、下一步：生产脚本 causal_judge.py 的实现方案（已设计未开工）

四级瀑布，每条边依次流过，产出三份草稿，**绝不写回正式数据**：

```
P0 队列：verified 且 evidence 为空的约 109 条（最大价值，第一步只做这些）
P1 队列：background 71 条复审
A级 本地语料裁决（冻结的 v3 prompt）
    ├─ causal+quote过验 → 补 evidence，source="events.json语料"
    ├─ background/unrelated → 降级/删除候选
    └─ insufficient ↓
B级 联网找证（复用 tools/detail_server.py：party_search /
    bing_official_search / wiki_extract / web_fallback / _site_label）
    查询策略：主查 B 标题（史书惯例果的条目回溯原因），
             辅查 core_term(A)+core_term(B)
    抓到 → 带「本地块+外部文本」重裁 → quote 在外部文本中过验才收
    限流 2~3s + fetch_cache\ 磁盘缓存
C级 conjecture 二段提问（放开知识限制 + 声明无文书推断）
产出：judge_report.md（四态归类）
     tier_plan6_draft.json（沿用现有 {upgrade/background/delete} 格式，
                           审完改名即可进 build_causality.py，流水线零改动）
     conjecture_edges.json（独立线索清单）
```

**分四步走，每步独立见效**：
1. A级 × P0 的 109 条（验收标准：补证率/伪引文率对比考试基线 88%/12%，不达标停）
2. 扩到 P1 的 71 条
3. 接 B 级联网
4. 开 C 级 conjecture

## 七、环境与已知坑

- Windows PowerShell 5.1 下 curl 是 Invoke-WebRequest 别名，调 Ollama 用
  `curl.exe` 或 python urllib（脚本已用后者）
- PowerShell 内联 python -c 含中文/花括号会被引号搞坏，复杂逻辑务必写 .py 文件再跑
- 控制台 GBK 打中文会乱码但不影响执行；脚本已做 `sys.stdout.reconfigure(utf-8)`
- events.json 键格式为不补零的 `year-month-day`（如 `1911-10-10`），比较必须数值化
  （脚本里 ktuple/ekey 已处理）
- backups/causality.json.bak-dedup-20260821-204846 是负例重建的数据源，别删
