# 因果图 · 外部增强方案（设想）

> 配套实现：本地启发式算法已落地（`CAUSAL_INFERRED`，89 条推断边 + 55 条已证实边，见 `index.html`）。
> 本文回答一个问题：**当本地数据不够用时，如何用外部知识把"因果"挖得更深、更广、更可信。**

---

## 1. 两种范式对照

| 维度 | 本地启发式（已做） | 外部增强（本文） |
|---|---|---|
| 数据来源 | 文件里已有的 `title` / `desc` | 史料库、百科、官方文献、知识图谱 |
| 方法 | 交叉引用匹配 + TF-IDF 文本相似 | LLM / 关系抽取模型从外部语料抽 "A 导致 B" |
| 是否需要联网 | 否 | 是（预计算阶段；运行时仍可零依赖） |
| 结果性质 | 抓"明文引用"与"主题相似" | 从外部知识推断"机制性因果" |
| 可信度来源 | 原文可追溯 | 须绑定权威文献出处，否则不可信 |
| 成本 | 0 | API / 算力 / 人工审核 |

**核心认知**：无论本地还是外部，"算"出来的本质都是**关联/相关**，不是哲学意义上的真因果。差别在于——外部增强能借助海量权威语料，把"关联"升级为"有据可查的机制性因果"，覆盖本地文案没写透的关系。

---

## 2. 外部数据从哪来

1. **结构化知识库**
   - Wikidata / DBpedia：实体、时间、relations（含因果/继承/促成类属性）。
   - 中文党史知识图谱（若有）：直接给"事件—事件"边。
2. **权威语料全文**
   - 《中国共产党一百年大事记》、人民网、共产党员网等官方文献。
   - 用于"远程监督"：在文献里找 "A……促成/导致/为……奠定……B" 的句式模式。
3. **模型**
   - 云端 LLM（GPT / 文心 / 通义等）：最强，但需 API key、联网、计费、脱敏。
   - 本地关系抽取模型（BERT + 关系分类，或 spaCy 流水线）：可离线，**与当前单文件静态站架构最契合**。

---

## 3. 处理流水线

```
现有事件(标题/日期)
        │
        ▼
[1] 候选对生成   按时间先后(A 在 B 前)生成事件对，并用知识库检索 A、B 的相关实体/文献
        │
        ▼
[2] 关系抽取   对每对(A,B)：
        │          · LLM prompt：「判断 A 是否促成/导致 B，给置信度0-1与一句话理由」
        │          · 或远程监督：在文献中匹配「A … 导致/奠定/促成 … B」模式
        ▼
[3] 置信度融合   综合 = w1·本地信号(交叉引用/相似) + w2·外部抽取分 + w3·出处权威度
        │
        ▼
[4] 分级归档   高置信 → 并入 CAUSAL(已证实, 金标准)
        │         中置信 → 并入 CAUSAL_INFERRED(推断, 虚线)
        │         低置信 → 丢弃
        ▼
[5] 人工审核回路   高/中置信建议由人工抽检确认，规避模型幻觉
        │
        ▼
[6] 增量更新   新事件自动接入，定期重跑流水线
```

---

## 4. 与本地启发式如何融合（三层模型）

```
┌─────────────────────────────────────────────┐
│ 已证实因果  CAUSAL      （人工 + 高置信外部）  │ 实线·红
├─────────────────────────────────────────────┤
│ 推断关联    CAUSAL_INFERRED（本地算法 + 中置信外部）│ 虚线·琥珀
├─────────────────────────────────────────────┤
│ 未连接事件  （既无本地信号也无外部证据）        │ 不出现在图里
└─────────────────────────────────────────────┘
```
视觉上和现在一致：同一张网络图，两种边。区别只是"推断"这一层的来源从"纯本地"扩成"本地 + 外部"。

---

## 5. 成本 / 风险 / 隐私

- **成本**：云端 LLM 按调用计费、有延迟；本地模型需一次性训练/下载，但运行时免费。
- **风险（最关键）**：模型**幻觉**——可能编造看似合理实则错误的因果。对党史这类**史实准确性要求极高**的领域，必须有"可溯源"约束：每条外部边都必须附**具体文献出处**，否则不进图。
- **隐私**：本地数据默认不上云；若走云端 LLM，需对事件文本脱敏（去掉无关个人信息，本数据本身已不含个人敏感信息）。
- **可控性**：外部结果应是**预计算 + 人工兜底**，而非"运行时让模型现编"。这样既能享受外部知识，又不破坏单文件零依赖、可离线打开的产品形态。

---

## 6. 落地路线（分阶段）

- **Phase 0（已完成）**：本地启发式 —— 交叉引用(强) + TF-IDF 相似(弱)，生成 `CAUSAL_INFERRED`，UI 加"显示推断关联"开关。
- **Phase 1（建议下一步）**：离线脚本 + 云端 LLM 批量抽取，产出 `CAUSAL_EXTERNAL` 候选清单（带出处与置信度），人工审核后并入。仍**预计算、不联网运行时**。
- **Phase 2（可选）**：训练/接入本地轻量关系抽取模型，完全离线生成外部边，与现有架构零冲突。
- **Phase 3（可选）**：在线"问问 AI：这件事的因果链？"——调用云端模型做交互式追问（需 key 与联网，作为增值功能而非核心）。

---

## 7. 结论

外部增强能**扩覆盖、提精度、补机制解释**，但前提是"**可溯源 + 人工兜底**"。对当前这个单文件静态站而言，最优形态始终是**预计算注入**（和本地启发式同一套路），而不是运行时联网——这样既借到了外部知识的力，又保住了"双击打开、离线可用、零依赖"的产品底线。
