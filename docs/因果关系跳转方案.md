# 因果关系跳转事件 · 实施方案

> 目标：让时间轴上的事件不只是按时间先后排列，而能按"为什么发生 / 导致了什么"顺藤摸瓜地跳转浏览。

## 一、核心思路
把"因果"建模为事件节点之间的**有向关系边**，而非单纯的时间先后。用户既能上溯"前因/背景"，也能下探"后续"，并可在时间轴上把整条因果链高亮出来。

## 二、数据层：给关键节点加字段
- 在 `historyData` 每条事件上可选加 `causes` / `causedBy` 两个字段，值为"年-月-日"字符串数组（即事件唯一键 `key = year + '-' + month + '-' + day`）。
- 关系语义：
  - `causes`：本事件 → 导致了哪些事件（下游）
  - `causedBy`：本事件 ← 由哪些事件导致（上游）
  - `background`（可选）：背景/条件，弱因果，作上下文不直接成链
- **单一方向标注**：只写 `causes`，`causedBy` 由程序反向遍历推导，避免重复维护。
- 先只给 **30–50 个核心节点**（如五四运动、中共一大、建国、十一届三中全会、改革开放、港澳回归等）建边，降低标注成本。

## 三、交互层：弹窗"因果脉络"区
- 在 `openModal`（事件详情弹窗）底部新增"因果脉络"区：
  - 列出"前因（N 件）"与"后续（M 件）"的可点击链接；
  - 点击复用现有 `openModal(key)` 直接跳转，无需关闭重开；
  - 悬停显示标题摘要，点击平滑过渡。
- 同一逻辑适用于会议弹窗 `openMeetingDetail`。

## 四、时间轴"因果高亮"模式
- 时间轴工具栏新增"因果脉络"开关：选中某事件后，沿因果链（上溯 causedBy、下探 causes）把所有相关卡片**描边/加底色高亮**，并在轴上用连线或箭头把这条链画出来，一眼看清"从哪来、到哪去"。

## 五、可选：关键词启发式自动建议（降成本）
- 正则扫描 `title`/`desc` 中含"标志""奠定""由此""引发""促使""为…奠基""序幕"等词，自动建议候选因果对，人工确认后入库，减少逐条手标。

## 六、落地建议（分两步走）
1. **第一步（体感强、改动小）**：数据层 + 交互层（弹窗因果脉络）。先挑 30–50 核心节点把 `causes` 建起来，跑通弹窗跳转。
2. **第二步（视觉最炫、工作量略大）**：时间轴"因果高亮"模式。
3. 关键词启发式作为持续标注的辅助，并行推进。
